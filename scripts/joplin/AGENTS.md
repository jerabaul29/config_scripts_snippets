# Script for good practice run of Joplin AppImage

This should describe how to design a small bash script compatible with modern Ubuntu distros (24 and newer, wayland only). The script should be in this folder, self contained, and named: `joplin_run.sh` .

The goal of the script is to make it easier to use Joplin in a safe way: making sure it is updated, and running well isolated with minimum sets of rights with bubblewrap. All assumptions should be documented in comments and code as necessary. Any issue or non fulfilled assumption should result in crash, abort, error code, and print an explanation comment

Make sure the .sh script and this .md file are kept in sync and reflecting each other.

Script structure and maintenance:
- The script is organised as small functions (one per task below) called in order from `main`, with shared helpers for the repeated ownership checks (`require_real_dir`, `require_own_file`, `require_not_shared_writable`).
- After any edit run: `bash -n joplin_run.sh`, `shellcheck joplin_run.sh` and `shfmt -i 4 -ci -bn -d joplin_run.sh` (all must pass with no output; `shfmt -w` rewrites in place).

Assumptions about the system setup:
- There is one or more Joplin AppImage and associated sha512 files under `$HOME/Desktop/Software/Joplin` ; only the latest and most up to date should be run.
- The appimage can be run and the necessary packages are on the system so it runs without error - this is the user's responsibility.
- The bubblewrap (`bwrap`) program is installed - this is the user's responsibility.

Rules for the bash script:
- Use a preamble that makes bash as safe as possible: strict mode, `umask 077`, fixed `PATH=/usr/bin:/bin`, unset `BASH_ENV`, `ENV`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, and refuse to run as root.
- Strip control characters from error messages before printing them.
- Take a non-blocking `flock` on a lock file in `$XDG_RUNTIME_DIR` so two instances cannot run at once (the lock is not inherited by Joplin).
- Make sure the script is always safe to run.
- Code defensively: make sure that any failed assumption or failed command makes the script abort and print an error message + return an error code.
- Check all assumptions actively, in comments and in code. Assumptions that may or may not hold are tested by running code (tool flags, `sort -V`, `pgrep` exit 1, a sandbox probe, and a status-fd preflight), not merely documented.

Tasks that the bash script should implement and run in sequence (any failure should abort with error message and error code):
- Target Ubuntu 24.04 or newer only (`ID=ubuntu` and `VERSION_ID` >= 24.04; `ID_LIKE` is not enough) with a Wayland session only (`XDG_SESSION_TYPE=wayland`, plain `WAYLAND_DISPLAY`, owned non-symlink socket; X11 aborts) and an active systemd-resolved: abort otherwise (also abort if `/bin`, `/lib`, `/lib64` are not merged-/usr symlinks resolving to `/usr/bin`, `/usr/lib`, `/usr/lib64`, if `/etc/resolv.conf` is not the systemd-resolved stub, or if that stub does not list `nameserver 127.0.0.53`). `HOME`, the Joplin directory and `XDG_RUNTIME_DIR` must be real user-owned directories (`XDG_RUNTIME_DIR` not group/world accessible). Error messages from `wget` are included in aborts, with control characters stripped (only newline is kept).
- Before any network or sandbox use, check tool assumptions that may be false: `bwrap` is not setuid/setgid and its `--help` lists every flag the script passes; `wget` supports `--https-only`, `--no-config`, `--no-proxy` and `--no-netrc`; `sha512sum` supports `--strict`; `setsid` supports `-f`/`--fork`; `sort -V` orders `1.10` after `1.2`; `pgrep` exits 1 when nothing matches.
- Find the latest local version of the appimage in `$HOME/Desktop/Software/Joplin` and print it for the user.
  - File naming format: `Joplin-3.7.21.AppImage` with associated `Joplin-3.7.21.AppImage.sha512` (3.7.21 is only an example; the actual version may differ and be more recent).
  - "Latest" is determined from the version in the file name (version sort, e.g. `sort -V`), not from file modification time.
- Before checksum verification, require the AppImage and `.sha512` to be regular files (not symlinks) owned by the current user and not group/world writable.
- Check that the sha512 for the latest local version (.sha512 corresponding file, exactly one entry naming the AppImage) is correct according to `sha512sum --strict -c` and print it for the user.
- Get the latest version available by `wget https://github.com/laurent22/joplin/releases/latest` : use wget (`--no-config --https-only --no-proxy --no-netrc --max-redirect=5`, so `~/.wgetrc`, proxy variables and `.netrc` cannot weaken or redirect TLS) to fetch the page (e.g. `wget -qO-` to stdout), then match the version in its output (next step).
- Use a regexp with field capture to find the latest version released: it should be the first match for a string in the wget output looking like https://github.com/laurent22/joplin/releases/tag/v3.7.21 (note version is v. some number . some number . some number), and print the corresponding version for the user.
- Check that the appimage version is equal to the latest github release version, and print confirmation to the user.
- Authenticity: download the `Joplin-X.Y.Z.AppImage.sha512` published in the GitHub release for that version over HTTPS and require it to contain exactly one entry (naming the same AppImage, if it names one) whose hash equals the local checksum (this also proves the release tag exists). The local checksum alone only proves integrity.
- Check that Joplin is not already running (abort with an error if it is): use `pgrep` for the current user's processes matching the AppImage file name (`Joplin-X.Y.Z.AppImage`), the sandbox launch path `/opt/Joplin.AppImage` (this is what finds a sandboxed instance), or a `/.mount_Joplin*` mount (an unsandboxed instance); `pgrep` exit code 1 means not running, any other non-zero code is an error. Print confirmation to the user.
- Prepare: run a private copy of the AppImage (in a `mktemp -d` directory under `$XDG_RUNTIME_DIR`, removed on exit) and re-hash the copy against the verified checksum, so the bytes cannot change between check and launch. Require `$HOME/.config/joplin-desktop` to be a real directory (no symlink) owned by the user. Rotate the log file at 1 MiB (the log must be a regular file, not a symlink, owned by the user).
- Start the AppImage with bubblewrap (see the bubblewrap rules under), detached with `setsid -f` (own session, stdin from `/dev/null`, stdout/stderr appended to `${HOME}/.local/state/joplin_run.log`) so Joplin keeps running if the terminal is closed or killed, inside a `systemd-run --user --scope` with `MemoryMax=4G`, no swap and `TasksMax=2048` (a preflight checks the scope works). Use `APPIMAGE_EXTRACT_AND_RUN=1` so the verified AppImage does not need FUSE inside the sandbox. Use `bwrap --json-status-fd` to obtain the sandbox child PID; for about 3 seconds watch for an `exit-code` report, then require the PID to be alive (`kill -0`), otherwise abort with an error. Before launch, a preflight runs the same `setsid`/`systemd-run`/`bwrap` fd 3 chain with `sleep` and aborts unless the reported PID is a live host PID of `bwrap` in a different pid namespace; that process is then stopped.

Bubblewrap rules (keep these rules in sync with `joplin_run.sh`):
- By default, everything not needed is locked away.
- Expose only `/usr` read-only for the application runtime, with `/bin`, `/lib` and `/lib64` as symlinks into it. Expose read-only only: TLS certificates, fonts and `/etc/localtime`. The identity and name-service files `/etc/passwd`, `/etc/group`, `/etc/hosts`, `/etc/nsswitch.conf` and `/etc/resolv.conf` are synthetic, minimal, generated per run (so the host user name, host name, search domains and NSS modules are not leaked; DNS uses the systemd-resolved stub at `127.0.0.53`, reachable through the shared network). Use `--hostname joplin`. Pass through only `LANG` and `LANGUAGE` (validated against a safe character set); other `LC_*` values and locale configuration are not exposed. `XDG_*` variables other than `XDG_RUNTIME_DIR` (and `TMPDIR`) are not set (their defaults already resolve inside the sandbox home and `/tmp`).
- Provide isolated writable `/tmp` (2 GiB cap) and home/cache/state paths (512 MiB cap). These are temporary RAM-backed tmpfs and are not host directories; the AppImage extracts about 400 MB into `/tmp`. Sizes and the memory limit are constants at the top of the script.
- Allow persistent read/write access only to `$HOME/.config/joplin-desktop`.
- Create `/tmp/joplin_sharedrop` if needed with owner-only host permissions, and expose it read/write inside the sandbox as `/home/joplin/Sharedrop`. This is a two-way exchange location: both the host user and Joplin can read, create, modify and delete files there, and its contents may be cleared when `/tmp` is cleaned.
- Allow the active GUI connection only: one Wayland socket (`$XDG_RUNTIME_DIR/$WAYLAND_DISPLAY`, where `WAYLAND_DISPLAY` must be a plain name like `wayland-0`; absolute paths are rejected). X11 is not supported or exposed; the script aborts if no Wayland socket is available. Do not expose the rest of the user's home or session runtime sockets.
- Additionally: explicit `--unshare-user`, `--uid` and `--gid` of the invoking user (do not rely on bwrap's default uid map; uid 0 must not be used), `--unshare-cgroup` (no `-try` fallback), `--new-session` and `--cap-drop ALL`; `/run/joplin` is mode 0700. Chromium runs with `--ozone-platform=wayland --disable-gpu` and `GDK_BACKEND=wayland`. Do not add `--no-sandbox`; Ubuntu 24.04 AppArmor may restrict unprivileged user namespaces for `bwrap` (the preflight reports this). Do not pass `--share-net`: this bwrap accepts it only with `--unshare-all`. Network stays shared because `--unshare-net` is omitted; the preflight compares namespace ids and aborts if they differ.
- Pass the GNOME GTK theme and color-scheme selection (read with `timeout 5 gsettings`, required; unexpected values abort) as the `GTK_THEME` environment variable, rather than exposing the user's desktop settings database or D-Bus.
- Isolate the PID, IPC, and UTS namespaces. Leave the network namespace shared with the host so Joplin Cloud can connect.
- Known residual risk: with the shared network and the full data directory, Joplin or any plugin it loads can read every note, the sync token and the Sharedrop contents and send them anywhere. The sandbox can also reach host localhost services and abstract unix sockets. Not mitigated here; a host firewall/proxy or `--unshare-net` with an allowlist proxy would be needed. Wayland also gives access to the clipboard.
- Bubblewrap cannot limit shared networking to Joplin Cloud. This configuration permits Joplin general network access; restricting it to Cloud requires a separate host firewall or proxy.
- OpenSnitch may be used as a separate application firewall to allow verified Joplin Cloud destinations and deny other outbound connections (not implemented yet). If doing so, would need to check that it correctly identifies Joplin's processes when launched through Bubblewrap and AppImage extraction before relying on those rules.
- GPU devices, audio, D-Bus/portals, keyring, notifications, and arbitrary host files are not exposed. Grant them separately only if a needed feature requires them. File import/export outside Joplin's data folder and the Sharedrop folder is intentionally unavailable by default.
- Before launch, the script runs a check inside the configured sandbox that verifies Bubblewrap mounts and namespace support, that the data, Sharedrop and home directories and `/tmp` are writable, and that the Wayland socket is present. The same probe aborts unless uid/gid match the invoking user, the hostname is `joplin`, capabilities are dropped, user/pid/ipc/uts/cgroup namespaces differ from the host, the network namespace matches the host, synthetic `/etc` files match what was generated, `/usr` is read-only, `/bin` `/lib` `/lib64` are the expected symlinks, and GPU, audio, X11 and D-Bus paths are absent. The host must permit the namespaces Bubblewrap needs; an installed `bwrap` alone is not sufficient.
