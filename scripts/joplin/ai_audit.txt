AUDIT OF joplin_run.sh AND AGENTS.md
===================================
Date: 2026-10-09
Scope: static read of both files; nothing was run or changed.
Overall: the script is already well hardened. Findings are ordered by impact.


HIGHEST IMPACT: RESIDUAL RISKS
------------------------------
1. Shared network + full data directory allows exfiltration.
   - Joplin, or any plugin it loads, can read every note and the sync token
     and send them anywhere.
   - Because the network namespace is shared, the sandbox can also reach
     localhost services (dev servers, 127.0.0.53) and abstract unix sockets.
     That includes the abstract X11 socket, so the file bind alone does not
     limit X access.
   - Safer options:
     * --unshare-net plus a host-side allowlist proxy reached through a bound
       unix socket.
     * OpenSnitch rules, as the doc already notes.
   - At minimum, state the abstract-socket and localhost exposure in AGENTS.md.

2. The X11 fallback is much weaker than Wayland.
   - Any X11 client can keylog and screenshot other windows and inject input
     through XTEST. That largely defeats the isolation.
   - The script falls back to X11 silently.
   - Fix: make X11 opt-in (e.g. JOPLIN_ALLOW_X11=1) or print a loud warning,
     and document it.
   - Wayland also exposes the clipboard, but is far less severe.

3. The whole ~/.Xauthority is bound in.
   - It can hold cookies for other displays and hosts.
   - Fix: build a minimal file with `xauth nextract`/`nmerge` for the current
     display only.


VERIFICATION AND UPDATE LOGIC
-----------------------------
4. The sha512 check proves integrity, not authenticity.
   The .sha512 file sits next to the AppImage, so anyone who can write the
   directory can replace both.
   Fix: download the release's .sha512 over HTTPS and compare it to the local
   file. That ties the file to GitHub's release.

5. Time-of-check/time-of-use gap.
   The AppImage is hashed, then bind-mounted later by path. Low risk, since an
   attacker would need to be the same user.
   Fix: copy the file to a private mktemp directory, hash the copy, bind the
   copy.

6. wget honours ~/.wgetrc and proxy variables.
   A bad check_certificate=off setting would weaken TLS.
   Fix: add --no-config --https-only --max-redirect=5.

7. The release regex matches the first tag link in the page.
   That could be the wrong tag if GitHub's markup changes. It matches the spec.
   Option: also check that the redirect target (wget --server-response, final
   URL) agrees with the match.


SCRIPT ROBUSTNESS
-----------------
8. Root is not refused; PATH and environment are not sanitised.
   - Add: ((EUID != 0)) || die
   - Set PATH=/usr/bin:/bin at the top.
   - unset BASH_ENV ENV LD_PRELOAD LD_LIBRARY_PATH
   - The `command -v` checks trust whatever is on the user's PATH.

9. No lock.
   Two concurrent runs can both pass the pgrep check. Use flock on a lock file.

10. The post-start check is weak.
    - pgrep can match an unrelated process (e.g. an editor with
      Joplin-x.AppImage in its arguments) and give a false "started".
    - sleep 2 is arbitrary.
    - Fix: use bwrap --info-fd or --json-status-fd to capture the child PID,
      then check kill -0 or /proc/$pid.

11. The preflight runs only /usr/bin/true.
    It does not test that the data directory is writable inside the sandbox or
    that /tmp allows exec. Add `test -w` on the data directory inside the
    sandbox.

12. The data directory is not checked.
    ~/.config/joplin-desktop has no ownership or symlink check, unlike
    sharedrop. Add -O and ! -L.

13. The log file is unbounded.
    No rotation, and no symlink or ownership check on the log path.

14. Terminal escape sequences can reach the terminal.
    die prints pgrep and sha_out raw, which can include process arguments.
    Strip control characters before printing.

15. Minor items:
    - Set LC_ALL=C for sort -V.
    - Add --strict to sha512sum -c.
    - Validate LANG and LC_* values, not just the variable names.
    - Use `timeout 5 gsettings`.
    - The trailing `|| die` after the ERR trap is redundant, and die inside
      $() can print two messages.


SANDBOX HARDENING
-----------------
16. Add these bwrap flags:
    - --unshare-user and --cap-drop ALL, to make the intent explicit.
    - --new-session, as defence in depth next to setsid.
    - --unshare-cgroup-try.
    - --hostname joplin.
    - --perms 0700 on /run/joplin.

17. Cap memory.
    --tmpfs /tmp and the tmpfs home are unbounded RAM, and the extract-and-run
    AppImage unpacks about 400 MB into /tmp. Use bwrap --size, or run under
    `systemd-run --user --scope -p MemoryMax=...`.

18. Identity leak.
    The real /etc/passwd exposes the username and full name. Generate a minimal
    passwd and group, or use --uid/--gid mapping.

19. /bin and /lib are bound as real directories.
    On Ubuntu they are symlinks into /usr. Use `--symlink usr/bin /bin` when
    the host path is a symlink. The current approach works but is fragile.

20. Do not add --no-sandbox to work around Electron's own sandbox.
    Keep Chromium's userns sandbox nested inside bwrap. Ubuntu 24.04 AppArmor
    can restrict unprivileged user namespaces, a likely cause if the preflight
    fails.


AGENTS.md vs SCRIPT MISMATCHES
------------------------------
- Process-match pattern.
  * The doc says pgrep matches Joplin-X.Y.Z.AppImage or /tmp/.mount_Joplin*.
  * The script also matches /opt/Joplin.AppImage and /.mount_[Jj]oplin.
  * With extract-and-run there is no .mount_ path at all.
  * The /opt/Joplin.AppImage match is the one that actually finds the
    sandboxed process.
- GTK theme. The doc says GTK_THEME comes from gsettings only. The script also
  passes through a host GTK_THEME when gsettings is missing.
- Behaviour the script has that the doc does not describe:
  * --clearenv.
  * The Wayland-to-X11 fallback.
  * DISPLAY validation.
  * Sharedrop symlink and ownership checks.
  * The refusal to run with an unexpected color-scheme.
  * The /dev and /proc mounts.
  * The sleep 2 post-start check.
- Risks the doc does not mention: items 1, 2 and 3 above, and plugin exposure.
- Wording. "Joplin can read dropped files but cannot modify or export" is only
  true within the sandbox; the network can still carry the contents out.
